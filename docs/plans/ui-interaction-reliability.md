# UI 交互可靠性与导航收敛实施方案

## 决策与范围

用户授权：编写方案，由 `xai/grok-4.6`、`high` 推理级别执行。基线提交：`c5125fc`（personal）。

目标不是换皮，而是让用户可信地停止任务、恢复消息、看到结果并定位当前位置。合并两轮源码审查为下面七个工作项；搜索失败反馈和定位收敛属于同一项，不建立两套机制。

审查发现以源码为依据，竞态和 SDK 队列的数据损失尚须针对性核验。实现前核对当前源码，行号仅为定位线索，不把假设当已复现事实。

## 执行次序与验收

每项实现后立即运行相关测试。发现不能可靠解决的 SDK 限制或竞态，明确记录阻塞，不用静默丢弃或虚假的成功状态掩盖。完成状态以行为验证为准，不以测试数量为准。

### 1. Escape 只处理当前交互层

证据：`components/SettingsPanel.tsx` 的 document keydown 消费 Escape，但 `hooks/useKeyboardShortcuts.ts` 的 window 监听未检查 defaultPrevented，仍可能调用全局 abort。

实现：
- 全局快捷键忽略已消费事件；设置关闭处理在需要时停止继续传播。
- 保留无弹层时 Escape 停止任务，以及 ChatInput 内现有菜单关闭/停止语义。
- 顺手检查相关现有弹层是否存在同一传播问题，但不建设全局弹层框架、不扩大为全量可访问性重构。

验收：设置打开且焦点位于非输入按钮时，Escape 关闭设置但不 abort；无弹层的同一事件仍可 abort；已消费的其他快捷键不重复执行。测试必须执行事件/处理器行为，而不只正则匹配源码。

### 2. 停止覆盖整个提交生命周期

证据：`hooks/useAgentSession.ts` 的 handleSend 先显示运行状态，再等待创建会话、模型设置、SSE 连接后发 prompt；handleAbort 无 sessionId 时返回，没有取消等待中的提交。

实现：
- 复用现有运行编号，记录该次提交的取消意图，处理所有必要 await 边界，尤其真正派发 prompt 之前。
- 未发送时取消本次待提交工作，清理对应乐观状态，并通过已有草稿恢复逻辑保留文字和附件，避免影响后续 run。
- 已发送时请求服务端 abort；不能把取消本地 fetch 等同于服务端停止。保留 SSE/GET 对账及旧运行隔离。
- 停止请求失败通过现有 Notice 呈现，不只 console.error。
- 检查 bash 启动是否存在相同缺口，如共用“停止”契约则做等价的局部修正；不要重写整个 Hook。

验收：在创建会话、连接 SSE 等阶段延迟 Promise 并点击停止，恢复 Promise 后不再发 prompt；取消旧 run 不影响新 run；已发送任务仍按真实状态完成收敛；失败不伪装停止成功；文字/附件不丢失。

### 3. 图片排队与撤回保持完整消息

证据：sendStreamingPrompt 可发送图片；客户端 queuedMessages、clear_queue 返回消费和 prependText 恢复路径却以字符串为单位。

先核验：追踪已安装 SDK 的 prompt 排队、队列更新、clearQueue，以及 `lib/rpc-manager.ts` 的适配，确认图片究竟在哪里保存/丢失。提交前把核验结论写入本方案的执行记录。

实现：
- 优先在真实队列数据的权威边界返回完整消息（文字与图片），通过已有附件/草稿恢复能力消费它。
- 不按文本匹配客户端缓存补图，不维护无法应对多标签页和出队竞态的影子队列。
- 保留 steer/followUp 两种语义，以及服务端 prompt 原子决定排队还是开启下一轮的机制。
- 若 SDK 公共能力不足，先寻找清楚、最小的应用层边界修正；不要未经确认永久禁用图片排队。确实无法保证完整性时，记录具体阻塞并报告，不声称完成。

验收：纯文字、纯图片、混合消息、多条撤回、相同文字不同附件；空队列、多标签页已有队列、正在消费与撤回的边界。用模拟队列/会话，不清除真实用户队列。恢复后的消息完整且不重复。

### 4. assistant 图片答案正常渲染

证据：`components/ChatWindow.tsx` 的最终答案分类接受 image，而 `components/MessageView.tsx` 的 BlockView 未渲染 image。

实现：复用现有 imageSource、图片预览和受支持的图片数据格式，补齐 assistant 图片块。保留文本/思考/工具分流，不改变最终答案识别的正常语义。

验收：纯图片、文字图片混排、历史与流式路径；不显示空白最终答案；图片延迟加载时不破坏用户上翻阅读位置。优先复用现有滚动策略，不另建滚动系统。

### 5. 仅桌面端侧栏收起时显示当前会话标题

用户看过手机截图后确认：手机顶部标题收益不足，移除，不增加开关。此决定取代原移动端显示标题的方案。

实现：
- 仅桌面端在现有顶栏内、侧栏收起时显示单行省略的会话标题，点击复用现有会话信息面板。
- 未命名会话复用侧栏标题回退规则；新会话采用明确的新会话标签。
- 手机端通过侧栏识别会话，不渲染顶部标题；删除标题专用遮罩逻辑，恢复此前为标题让位的主题/语言快捷入口。不加工具栏行或配置开关。

验收：桌面有名/未命名/新会话、切换会话、侧栏开关及标题点击；手机窄屏/宽屏均不显示顶部标题，More 与统计、文件入口保持原有交互。

### 6. 重名文件/终端标签最短路径消歧

证据：文件标签取 basename，终端标签取目录末段，完整路径仅放 title。

实现：
- 在同一可见标签集合内，仅对冲突标签追加最短可区分父路径，例如 `route.ts · sessions`。
- 普通标签保持原样，保留完整路径 tooltip，同步可访问名称。
- 复用已有浏览器可用路径约定，覆盖斜杠、Windows 路径等项目既有规则，不在客户端引入 Node 路径模块。
- 展示名变化不改变 tab id、文件缓存键、激活/关闭行为。

验收：无冲突、两级以上同名父目录、根目录、Windows/混合路径、文件和终端标签冲突（若现有容器允许）、关闭一个冲突标签后恢复简短名称。保留已有键盘导航和中键关闭行为。

### 7. 搜索与阅读位置恢复共用有界定位

证据：`components/ChatWindow.tsx` 搜索最多额外拉取 200 条，找不到就完成处理；部分定位用 Number.MAX_SAFE_INTEGER 取消挂载上限。已有 `lib/chat-outline-jump.ts` 提供取消、有界窗口、游标停滞处理。

实现：
- 复用/适度提取现有大纲定位规则，让搜索及阅读位置恢复按目标所属分组挂载有界窗口，避免另写定位框架。
- 保留搜索命中高亮、展开所属过程组、阅读偏移恢复，以及快速切换目标时的旧请求取消。
- 找不到时明确反馈；区分“更早历史”和“其他分支”能可靠判断的情况。不能判断时仅说明未定位，不声称某个操作一定能找到。
- 若展示完整历史入口则复用现有入口，不自动切换分支、不无限分页或无限挂载。
- 执行前确认“有界”同时涵盖 DOM 挂载与加载终止条件；必须有取消、游标停滞/耗尽处理。

验收：当前窗口命中、更深历史命中、不存在/其他分支命中、快速连续跳转、取消、游标停滞、过程内 assistant 命中、恢复偏移；跳转后挂载窗口仍有限。

## 验收边界与后续部署检查

- SDK 私有结构仍是明确的维护耦合；升级时运行真实 Agent 契约测试。不可解析的 custom/extension 消息会使本次撤回失败并保留队列，而不是转换成用户消息。
- 没有针对真实会话进行停止/撤回，也没有重建当前服务。移动端 More、图片加载后的滚动保持、长历史跨分支导航仍需部署后进行浏览器/真机检查。
- 自动化包括真实 Agent 的本地队列、纯函数/异步派发、组件静态输出与现有源码约束；不冒充完整浏览器 E2E。
- 复核时还修复了一个等待结束事件模拟遗漏导致的测试挂起，以及队列包装器测试未销毁 idle timer 导致的整套测试不退出。最终全量测试正常退出，无需放宽超时。
- 需要上线时由用户执行 `scripts/pi-web-switch.sh git --rebuild`；代理不执行该命令。
