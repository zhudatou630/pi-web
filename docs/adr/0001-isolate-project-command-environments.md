# Isolate project command environments from the web host

Pi Web sanitizes the environment of its built-in project shells instead of exposing the Next.js host runtime wholesale. The agent `bash` tool and direct user shell commands remove `PORT`, `NODE_ENV`, and `NEXT_*` variables while preserving the SDK-managed PATH, Pi session metadata, and all other inherited values; explicit variables set by a project command still take effect. Third-party extensions retain control of their own tools and subprocesses so existing overrides and remote execution integrations are not intercepted.

Direct `!` / `!!` commands wait for extension binding and an attached browser event stream, then ask `user_bash` before executing. A supplied result is recorded once without local execution; supplied operations run unwrapped, with no host environment injection. Only the local fallback uses the sanitized project shell. Handler errors never fall back locally and the SDK's error notice is shown once. The handler wait counts as shell work for running state, replacement and prompt admission. Stop cancels its UI and prevents a late handler response from starting a shell; the existing pre-dispatch cancellation and post-bash subagent report delivery remain intact.
