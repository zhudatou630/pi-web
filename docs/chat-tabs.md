# 聊天标签与分屏

标签属于一个窗口组；当前显示哪个标签，不改变归属和顺序。单窗只有左组，分屏时左右组遵循相同规则。一个会话在工作区只打开一个标签。

| 操作 | 行为 |
| --- | --- |
| 侧栏单击未打开的会话 | 在焦点组打开预览；该组已有预览时原位替换，否则追加到该组末尾 |
| 侧栏点击已打开的会话 | 切换到它所在的组和标签，保留原归属、顺序及预览状态 |
| 双击固定、显式在新标签打开 | 已打开则原位固定并定位；未打开则在焦点组追加固定标签 |
| 在预览会话发送、追加或引导消息 | 原位固定，不改变位置 |
| 新建草稿 | 在指定组追加；侧栏预览不会替换草稿 |
| 草稿发送成为会话 | 保留所属组与组件身份 |
| 分叉会话 | 发起时先固定源预览；新会话在源会话所在组追加为固定标签，异步完成时只在源会话仍被选中的情况下切换过去 |
| 关闭标签 | 只移除该标签；当前标签关闭后优先选本组右邻，否则左邻；另一组不变 |
| 关闭本组最后一个标签 | 结束分屏，保留另一组的标签和当前选择 |
| 在溢出菜单中关闭标签 | 焦点移到下一项的关闭按钮；关闭末项则移到前一项；不再溢出时关闭菜单，焦点回到本组当前标签 |
| 拖动标签 | 组内拖动改变顺序；拖到另一组的标签条上则移入该组（插在竖线处），并成为该组当前标签、获得焦点；移空一组等同合并分屏 |
| 标签右键菜单 | 固定预览、移到另一侧窗格（未分屏时为“在右侧分屏打开”，只把这个标签放到右边）、关闭 |
| 开启分屏 | 当前标签留在左侧；把其右邻标签移到右组，没有右邻则取左邻；只有一个标签时右侧新建草稿 |
| 合并分屏（右侧窗口关闭按钮） | 左组在前、右组在后，各组内部顺序不变；保留当前焦点会话 |
| 窗口变窄无法分屏 | 与合并分屏相同，保留当前焦点会话 |

每组最多一个预览标签。合并时优先保留当前焦点标签的预览状态，否则保留合并后第一个预览；其余预览转为固定，所有标签内容保留。

例如左组是 `A、B`，右组是固定的 `C`。右侧获得焦点后单击未打开的 `D`、`E`，右组依次变成 `C、D（预览）`、`C、E（预览）`，左组始终是 `A、B`。点击侧栏的 `C` 只切回右组的 `C`，不会将 `E` 放到左侧。

版面：标签条始终在顶栏一行内。分屏时顶栏按分屏比例切成两段，各放一组的标签条，分屏线从顶栏贯穿到内容底部；不再有第二行。分屏开关在左段标签条尾部，进出用同一个控件。每个窗格都有一份会话工具图标（分支、历史、提示词、工具、子代理）；未聚焦的那份不可点，点它只是把焦点切过去。费用和上下文占用在各自输入框下方，由该窗格自己的会话刷新。文件面板开关是全局的，始终在右端。

标签图标与侧栏会话行状态一致：等待输入 > 运行中 > 已完成未查看。任一窗格的会话只有在页面可见、聚焦且两分钟内有实际输入时才记已读；后台或闲置页面不会吞掉通知。跨浏览器已读经现有轮询同步（见 `docs/settings.md`）；被收进溢出菜单的标签按同样优先级在溢出按钮上提示。

实现位置：`lib/chat-tab-state.ts` 保存标签归属和纯状态操作，`components/AppShell.tsx` 维护两组的当前标签及焦点。分组由 `ChatTabItem.pane` 决定；`splitChatTabId` 只是右组当前标签，不能用它推导组成员。所有聊天组件保留在同一份带稳定 key 的列表下，由 CSS Grid 决定位置，切换、分屏与合并不会重新创建保留的聊天组件。

## 刷新与返回

整个聊天工作区的元数据保存在当前浏览器标签页的 `sessionStorage`（`pi-chat-workspace`）：标签顺序、左右组归属、预览、两组当前标签、焦点组和分屏比例。只存会话 id，不存聊天内容或目录缓存；目录列表成功返回后按最新 catalog 恢复，已删除会话过滤掉，空组按现有合屏规则处理。手机或窄窗口仍按既有规则合并分屏。

URL 的有效 `?session=` 优先取得焦点：已有标签切回所属组，未打开的会话追加固定标签，不替换任何预览。不存在的 id 回退到保存的选择；显式 `?cwd=` 仍创建新聊天，不恢复旧布局。草稿内容继续走原来的草稿存储，保留旧版草稿元数据恢复路径；不采用上游“每个主会话一份右面板侧聊”模型。布局存储不可用时只放弃布局恢复，不影响聊天。

未命名侧聊在标签和 Agents 中统一按同一 family 的创建顺序编号（`Side chat 1/2`，中文“旁问 1/2”），与标签开关、排序无关；已有问句名称不改。

## 扩展主动结束会话

扩展 `ctx.shutdown()` 等待工作结束后只关闭对应 runtime。当前会话标签保留为只读，显示持续的结束通知；它不再自动重连，草稿、滚动位置、标签归属与另一窗格都不变。关闭后重新打开该会话（或显式刷新页面）可正常启动新的 runtime；会话文件若被扩展删除则不会在旧路径重新创建。详见 `docs/extensions.md`。

## 文件面板标签

右侧文件与终端标签共用一个标签条，交互尽量与聊天标签一致，但只有一组，没有分屏和移组。

| 操作 | 行为 |
| --- | --- |
| 拖动标签 | 文件和终端可任意混排；顺序存于 sessionStorage `pi-web:panel-tab-order`，未出现在顺序里的新标签追加到末尾 |
| 原位替换（预览文件被替换、终端重启） | 新标签继承旧标签的位置 |
| 标签右键菜单 | 固定预览、复制路径、复制相对路径（文件在 cwd 内时）、在文件树中定位（同上）、关闭、关闭其他、关闭右侧；终端只有关闭类 |
| 在文件树中定位 | 侧栏切到该标签的 cwd，展开资源管理器并收起变更列表和搜索，展开祖先目录、滚动到该文件并短暂标记 2 秒 |
| Delete 键 | 关闭当前聚焦的标签 |

移动端与聊天标签一样，不提供右键菜单和拖动。实现：`components/TabBar.tsx`，顺序函数在 `components/file-tab-state.ts`。
