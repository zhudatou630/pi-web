# 聊天标签与分屏

标签属于一个窗口组；当前显示哪个标签，不改变归属和顺序。单窗只有左组，分屏时左右组遵循相同规则。一个会话在工作区只打开一个标签。

本文的“固定标签”指非预览标签，界面上叫“保持打开”（Keep open，同 VS Code）；“置顶”只指侧栏的置顶会话，标签菜单里的置顶也是它。

| 操作 | 行为 |
| --- | --- |
| 侧栏单击未打开的会话 | 在焦点组打开预览；该组已有预览时原位替换，否则追加到该组末尾 |
| 侧栏点击已打开的会话 | 切换到它所在的组和标签，保留原归属、顺序及预览状态 |
| 双击固定、显式在新标签打开 | 已打开则原位固定并定位；未打开则在焦点组追加固定标签 |
| 在预览会话发送、追加或引导消息 | 原位固定，不改变位置 |
| 新建草稿 | 在指定组追加；侧栏预览不会替换草稿 |
| 草稿发送成为会话 | 保留所属组与组件身份 |
| 分叉会话 | 发起时先固定源预览；新会话在源会话所在组追加为固定标签，异步完成时只在源会话仍被选中的情况下切换过去 |
| 关闭标签 | 只移除该标签；当前标签关闭后优先选本组右邻，否则左邻；另一组不变 |
| 关闭本组最后一个标签 | 结束分屏，保留另一组的标签和当前选择 |
| 在溢出菜单中关闭标签 | 焦点移到下一项的关闭按钮；关闭末项则移到前一项；不再溢出时关闭菜单，焦点回到本组当前标签 |
| 拖动标签 | 组内拖动改变顺序；拖到另一组的标签条上则移入该组（插在竖线处），并成为该组当前标签、获得焦点；移空一组等同合并分屏 |
| 标签右键菜单 | 保持打开（预览标签）、置顶/取消置顶会话（同侧栏置顶，仅侧栏有对应行的会话；置顶预览标签时同时保持打开）、移到另一侧窗格（未分屏时为“向右分屏”，只把这个标签放到右边）、合并窗格（分屏时）、关闭、关闭其他、关闭右侧 |
| 手机长按会话标签（没有右键；iOS 不发 contextmenu） | 400ms 长按、滑动取消，菜单开在标签下方（标签仍可见，不重复标题），只有置顶/取消置顶、Fork、标为未读/已读（同侧栏行的同名操作）；没有分屏与标签管理。草稿、侧聊、子代理标签不响应长按。只有一个标签时没有标签条：当前会话的置顶在 ⋯ 菜单里（Fork session 旁），标为未读对正在看的会话没有意义 |
| 向右分屏（标签右键菜单；只有一个标签时也有，顶栏不再有按钮） | 同 VS Code 的 Split & Move：当前标签移到新的右组并获得焦点，左组显示它的相邻标签；只有一个标签时它留在左侧，右侧新建草稿 |
| 拖标签或侧栏会话行到聊天区另一半 | 拖动时那一半显示落点提示：左组标签（或侧栏行）放到右半边即移入右组，未分屏时就此分屏；右组标签放到左半边即移回左组 |
| 双击顶栏空白处 | 在该窗格新建草稿标签（同 VS Code 双击标签栏空白） |
| 结束分屏 | 顶栏没有合并按钮（同 VS Code）：任一标签右键「合并窗格」（左组在前、右组在后，保留焦点标签），或关掉、移走一侧的全部标签 |
| 窗口变窄无法分屏 | 与合并分屏相同，保留当前焦点会话 |

每组最多一个预览标签。合并时优先保留当前焦点标签的预览状态，否则保留合并后第一个预览；其余预览转为固定，所有标签内容保留。

例如左组是 `A、B`，右组是固定的 `C`。右侧获得焦点后单击未打开的 `D`、`E`，右组依次变成 `C、D（预览）`、`C、E（预览）`，左组始终是 `A、B`。点击侧栏的 `C` 只切回右组的 `C`，不会将 `E` 放到左侧。

版面：标签条始终在顶栏一行内。分屏时顶栏按分屏比例切成两段，各放一组的标签条，分屏线从顶栏贯穿到内容底部；不再有第二行。「+」紧跟最后一个标签。顶栏没有分屏按钮：从标签右键菜单或把标签拖到右半边分屏。

标签外观参照 VS Code：× 只在显示中的标签上常驻，其他标签悬停时才出现，位置始终保留、宽度不跳；未发送草稿的点占在 × 的位置，悬停按钮时变回 ×；手机只给显示中的标签渲染 ×，其他未发送草稿只留这个不可点的点；标签是圆角小块（与侧栏选中行同一种选中态，见 `docs/ui.md` Tabs and top bars）：焦点窗格的当前标签填 `--bg-selected`，另一窗格显示中的标签不填底，只用 `--text` 文字色，整条顶栏只有焦点窗格那一块底色；没有顶线或下划线。桌面标签最窄 120px，再窄就收进溢出菜单。预览标签的标题颜色浅一档（Cursor、VS Code 用斜体；这里没有斜体字形，也不用点状下划线，它在圆角块下像一道阴影）。每个窗格都有自己的顶栏条件工具和输入框（子代理入口、上下文圆环和费用读数都在该窗格的输入框里，见 `docs/ui.md` Composer），由该窗格自己的会话刷新；用键盘或鼠标使用某一窗格输入框里的入口（子代理、上下文圆环、本轮 Review），都会先把焦点切到该窗格。未聚焦窗格的顶栏工具不可操作（`inert`），点它只是把焦点切过去。文件面板开关是全局的，始终在右端。

标签状态点与侧栏会话行一致（`lib/session-status.ts`）：等待输入 = 出错 > 已完成未查看 > 运行中。任一窗格的会话只有在页面可见、聚焦且两分钟内有实际输入时才记已读；后台或闲置页面不会吞掉通知。跨浏览器已读经现有轮询同步（见 `docs/settings.md`）；被收进溢出菜单的标签按同样优先级在溢出按钮上提示。

实现位置：`lib/chat-tab-state.ts` 保存标签归属和纯状态操作，`components/AppShell.tsx` 维护两组的当前标签及焦点。分组由 `ChatTabItem.pane` 决定；`splitChatTabId` 只是右组当前标签，不能用它推导组成员。所有聊天组件保留在同一份带稳定 key 的列表下，由 CSS Grid 决定位置，切换、分屏与合并不会重新创建保留的聊天组件。

## 刷新与返回

整个聊天工作区的元数据保存在当前浏览器标签页的 `sessionStorage`（`pi-chat-workspace`）：标签顺序、左右组归属、预览、两组当前标签、焦点组和分屏比例。只存会话 id，不存聊天内容或目录缓存；目录列表成功返回后按最新 catalog 恢复，已删除会话过滤掉，空组按现有合屏规则处理。手机或窄窗口仍按既有规则合并分屏。

URL 的有效 `?session=` 优先取得焦点：已有标签切回所属组，未打开的会话追加固定标签，不替换任何预览。不存在的 id 回退到保存的选择；显式 `?cwd=` 仍创建新聊天，不恢复旧布局。草稿内容继续走原来的草稿存储，保留旧版草稿元数据恢复路径；不采用上游“每个主会话一份右面板侧聊”模型。布局存储不可用时只放弃布局恢复，不影响聊天。

草稿仍按浏览器标签页保存正文、引用和图片。历史编辑的目标只在内存里，因此编辑期间也只在内存保留草稿，避免刷新后误发到当前分支；取消编辑后恢复持久化。运行中的内置命令不会通过刷新回到输入框。确认删除会话时清理对应草稿，退出登录时清理本标签页的所有草稿。

未命名侧聊在标签和 Agents 中统一按同一 family 的创建顺序编号（`Side chat 1/2`，中文“旁问 1/2”），与标签开关、排序无关；已有问句名称不改。

## 项目文件夹丢失

会话仍可阅读，发送被拒绝时保留输入。普通会话可用输入框上方的「分叉到其他文件夹…」选择新目录：复制全部历史（包括其他分支），保留源会话，草稿随新会话打开。已恢复原目录的会话、旁问和子代理不支持此操作。目录选择和新建会话一样可以登记新的文件访问根；服务端只登记校验后的实际目录。

## 扩展主动结束会话

扩展 `ctx.shutdown()` 等待工作结束后只关闭对应 runtime。当前会话标签保留为只读，显示持续的结束通知；它不再自动重连，草稿、滚动位置、标签归属与另一窗格都不变。关闭后重新打开该会话（或显式刷新页面）可正常启动新的 runtime；会话文件若被扩展删除则不会在旧路径重新创建。详见 `docs/extensions.md`。

## 文件面板标签

右侧文件与终端标签共用一个标签条，交互尽量与聊天标签一致，但只有一组，没有分屏和移组。标签条开头固定「改动」「文件」两个视图，不能拖动或关闭（见 `docs/ui.md` File panel）；下表只说内容标签。

| 操作 | 行为 |
| --- | --- |
| 拖动标签 | 文件和终端可任意混排；顺序存于 sessionStorage `pi-web:panel-tab-order`，未出现在顺序里的新标签追加到末尾 |
| 原位替换（预览文件被替换、终端重启） | 新标签继承旧标签的位置 |
| 标签右键菜单 | 保持打开（预览标签）、复制路径、复制相对路径（文件在 cwd 内时）、在文件树中定位（同上）、关闭、关闭其他、关闭右侧；终端只有关闭类 |
| 在文件树中定位 | 右栏切到「文件」视图和该标签的 cwd，展开祖先目录、滚动到该文件并短暂标记 2 秒 |
| Delete 键 | 关闭当前聚焦的标签 |

移动端与聊天标签一样，不提供右键菜单和拖动。实现：`components/TabBar.tsx`，顺序函数在 `components/file-tab-state.ts`。
