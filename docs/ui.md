# UI conventions

Design notes moved out of AGENTS.md. Typography rules are enforced by `components/Typography.test.mjs`; modal rules by `components/ModalDialog.test.mjs`.

## Typography
- Three font roles, chosen by what the text *is*, not by which characters it contains:
  - **UI** `--font-ui` (Sarasa UI SC): all chrome — headings, labels, buttons, menus, tabs, sidebar and file-tree names, settings, stats labels *and* numbers, timestamps, counts, badges, status and error messages. Numbers that must line up use `font-variant-numeric: tabular-nums`, never mono.
  - **Prose** `--font-chat` (the OS fonts by default; Sarasa UI SC or LXGW WenKai by scheme): user/assistant messages (final answers), compaction/custom/subagent markdown, the composer, read documents (markdown file preview). Never hardcode prose to `--font-ui`. The steps (process) list is UI throughout — thinking and intermediate assistant text included — so expanding it does not switch faces.
  - **Code** `--font-mono` (Sarasa Term SC): only (a) verbatim content — code blocks, inline code, terminal, file viewer, diffs, expanded tool args/output in chat (a collapsed step row's one-line preview — command, pattern, path — is a UI label), ASCII diagrams, system prompt, boxed verbatim values (device code, slash-command usage signature) — and (b) the bash-mode composer. Text fields and inputs are UI even when an identifier is typed (paths, URLs, model ids, headers, branch names): a mono face inside a UI-font box read as a mismatch. Identifiers shown as labels (and the trust-dialog cwd), list rows, descriptions, headers, or property values (package names, sources, paths, versions, branches, IDs, command names, file names) are UI: mixing mono into a UI line made rows look disordered. Any code face must keep CJK = exactly 2 Latin columns (Sarasa Term, LXGW WenKai Mono), so a Latin-only mono is not acceptable.
  - No brand face in the chrome (the Departure Mono section titles were removed): sidebar section titles (Pinned, Projects, Archived, Needs you, Running, Recent, the time sections) are translated UI text in sentence case, 13px `--text-dim`, the rows' size one tier quieter, after Cursor.
- Font schemes (`hooks/useFontScheme.ts`, localStorage `pi-font-scheme`, applied pre-paint as `html[data-font]` by `app/layout.tsx`) only redefine `--font-ui` / `--font-chat` / `--font-mono` in `app/globals.css`; components never branch on the scheme. `system` (default), `sarasa`, and `wenkai` exist today; anything else stored (nothing yet, or the removed serif `claude`) reads as `system`. `system` sets prose to `--font-ui-fallback` (Segoe UI + Microsoft YaHei, PingFang, Noto CJK): it deliberately renders per machine and downloads no prose face, which suits most users; exported images and HTML then also depend on the viewer's local fonts. `sarasa` (Settings: Sans) is the bare stylesheet, no `data-font`: Sarasa UI SC prose. `wenkai` sets prose in LXGW WenKai (CJK and its own Latin in each face; curly quotes stay proportional). The family tops out at Medium and its Screen cut is already about Medium, so there is no real bold: CSS 400 matches WenKai Screen (~10 MB) and CSS 600 falls back to the original Regular (~8 MB, declared at `font-weight: 500`, fetched only when bold text shows), which the browser bolds. Bolding the thinner Regular keeps bold ~25% heavier than body instead of ~48%, so dense glyphs such as 鬱 clog less. Tuned for Chromium: Firefox synthesizes a much weaker bold (~10% more ink than body here), accepted because the user runs Chromium browsers. `html[data-font="wenkai"]` alone sets `font-synthesis: weight`: WenKai strokes are near-monoline, so uniform synthesized bold keeps its design; Sarasa has real 400/600 faces, so UI and code never synthesize. UI and code stay Sarasa in every scheme. `@font-face` downloads lazily, so only the selected scheme's faces are fetched. The serif scheme (Source Serif 4 + Noto Serif SC) and the Departure Mono pixel face were removed: few used them, and they cost ~11 MB of the package.
- All faces are the bundled web fonts in `public/fonts` (no `local()`, no opt-in): installed copies differed in cut/version per machine. Bump the `?v=` query when replacing a file, since `/fonts/*` is served `immutable`. Only Simplified Chinese and English are supported (no zh-TW locale).
- Exactly two weights: 400 and 600. Only these have real faces, and `font-synthesis: none` is on (except the `wenkai` scheme, whose only face has no bold; see above), so any other weight either collapses to Regular or differs per machine.
- 600 is for headings only (dialog/panel/section titles, markdown headings/`strong`/`th`). Never express selected, active, pressed, or clickable state with weight; use background, color, border, or an indicator bar. Buttons, inputs, list-item names, counts, badges, and small dim group labels stay 400.
- Long tab and list-row titles (chat tabs, file panel tabs, sidebar session and project names) fade out over their last 24px instead of ending in "…" (Cursor; `.fade-clip`): an ellipsis carries nothing and takes room. The fade appears only when the text overflows (a scroll timeline on a box that cannot scroll is inactive); browsers without scroll timelines keep the ellipsis. Process-step previews (commands, Thinking) fade the same way. Menus, paths and other labels keep the ellipsis.
- Text that clips (`overflow: hidden` / ellipsis) needs `line-height` >= 1.3: Sarasa UI descenders reach ~0.24em, so a `line-height: 1` box cuts g/y and the bottom of CJK.
- No italic in UI chrome: there is no italic face and synthesis is off, so CJK would stay upright anyway; mark states another way. Markdown `em` keeps `italic` and is upright unless a real italic face is installed.
- Three text tiers, measured on `--bg-panel` with per-mode targets (`components/Typography.test.mjs`): light `--text` >= 15:1, `--text-muted` 8–8.5:1, `--text-dim` 5.2–5.5:1; dark `--text` >= 13:1, `--text-muted` 9.5–10.5:1, `--text-dim` 6.5–7.5:1. One WCAG target for both modes read crowded in light and spread in dark (APCA); Cursor's alpha tiers (100/74/60%) land on the same asymmetry. `--text` is content, `--text-muted` headings/sidebar items/labels, `--text-dim` metadata (CJK at 11px is why light dim stays above 5.2:1). Choose shades by these numbers; do not add ad-hoc grays, and do not permanently fade a tier with `opacity` (that is an unmeasured fourth gray). Opacity that toggles back to 1 for a state such as disabled/streaming is fine.
- Font sizes come from one scale. UI chrome uses four: 10 badges/tags/uppercase labels, 11 metadata (times, paths, process steps), 12 UI body and section headings (headings add 600), 14 dialog/panel/detail titles. The settings dialog is a form surface one tier up: 14 labels/nav, 13 descriptions/controls/tables, 16 group and detail titles, `--ui-row-height` controls, 15px nav icons. Reading content: 14 chat body, 13 dense content only (code blocks, file viewer, terminal, Mermaid source, markdown tables/file preview). Exceptions: 16 login input (iOS focus zoom) and device code, 20 glyphs (close ×, login brand). Inputs keep their designed size on touch too: iOS focus zoom is stopped by `maximum-scale=1` (`hooks/useViewportHeight.ts`), never by a blanket 16px rule (`components/Typography.test.mjs`). Chat-relative sizes use `calc(<11..14>px + var(--chat-font-size-offset, 0px))`. No half sizes; pick the tier by role. One chrome exception, after Cursor's sidebar: the session sidebar's list rows (session titles, project names, nav rows, rename field) are 13px in 32px rows.
- Icons are sized to the text they sit with: box = text size + 1 (11px text → 12, 12px → 13, 13px → 14), which puts a 24-unit icon's ink at CJK-glyph height. Icon-only buttons take the text tier of their bar (composer toolbar, panel toolbars: 12px → 13); the top bars (chat top bar, file panel header, tab strips' + and the sidebar's toolbar) take Cursor's 16px boxes, stroke 1.7 (see Tabs and top bars). 10px is reserved for micro glyphs (chevrons, close ×); otherwise 16 only for the top bars above and text-less overlays/avatars. Stroke stays ~1.1px on screen: `strokeWidth = round(1.1 × grid / size, 1)` (24 grid: 12→2.2, 13→2, 14→1.9, 16→1.7; micro 3, or 1.3 on a 10 grid); sized icon components use `iconStroke(size)` (`components/iconStroke.ts`). Color: an icon takes the color and state of its row (render it with `currentColor` from the shared parent, no own tier, no `opacity` fade; this includes file-type icons, provider logos, menu items). An icon never sits a tier above the word it labels: line-drawn glyphs carry more ink than letters and read heavier at the same color. Align by ink, not by box: a glyph with a low mark (the terminal `>_` underscore) is drawn so its ink sits on the text baseline. Icon-only buttons rest at `--text-muted` and hover to `--text`; top-bar icons and a tab's close × rest one tier lower at `--text-dim` (see Tabs and top bars). Only disclosure chevrons may sit one tier lower (`--text-dim`). Accent/semantic colors mark state (selected check, error, info), never a resting icon. Center icon and text with flex `align-items: center`, no ad-hoc `translateY` nudges or `vertical-align: middle` (it sits on the x-height). The one measured exception: Sarasa UI inks 11px text ~0.9px above its line-box centre, so icons in 11px metadata rows (answer footer, message actions) take the shared `.meta-row-icon` / `.message-action-button svg` lift in `app/globals.css`. State dots (below) are not icons and take none of these size rules. Short state labels in the composer toolbar are lowercase ids (`medium`, `configured`, `chat-only`); menu rows use translated sentence-case names (the thinking menu's High, the `⋮` menu's Tools · Configured, Compact 54%).
- Enforced by `components/Typography.test.mjs`.

## Sidebar top row and grouping
- Cursor's layout. The sidebar starts with a toolbar row as tall as the chat's top bar: the sidebar toggle (desktop with the sidebar open; otherwise it leads the chat top bar, one element in one place; the same left-panel glyph in both places), search, and at the far end "Group and filter" then Settings as a vertical ⋮ (chosen as the lightest mark: a gear, sliders and Cursor's Customize blocks read heavy; its tooltip and accessible name say Settings). Then 32px nav rows of 13px text, icon in the folder icons' column: New Session (title case, as Cursor's New Chat; Cursor's paper-plane glyph), current (tinted) while the new-session page shows; Routines (Cursor's robot glyph for Automations), pressed while the Routines page shows (a second click returns to the chat). New session opens a draft at the sidebar's selected cwd (no project yet: the folder picker); the project row's hover + stays for a specific project. There is no Projects header toolbar. There is no footer: Cursor's holds the account, which Pi Web does not have, and VS Code's Agents window has none; the list keeps that height.
- One column, measured on Cursor: row highlights sit 8px from the sidebar edges (`--sidebar-inset`, never under 8); inside a highlight the leading mark (folder, nav icon, state or idle dot, selection box) is centered 15px in and the label starts 32px in; section titles start 9px in. A section header is a 32px row with 12px of air above it (Cursor's spacing between groups); no rules between sections. Toolbar and nav icons follow Cursor's measured glyphs: 16px boxes (stroke 1.7 per the icon scale, about Cursor's weight), ink about 12–14px, resting at `--text-dim` (a tier lighter than their labels) and coming up with the row on hover or when current; folders and row actions stay 14px.
- Search is a palette, not a field in the list (Cursor's): the search button opens a dialog near the top of the window with a field over the eight most recent unarchived sessions (state or idle dot, title, project, time); typing replaces them with full-text results (`SessionSearch`). ↑/↓ walk the rows, Enter opens the focused row (from the field, the first), Escape or a click outside closes.
- "Group and filter" menu (after Cursor's / VS Code's Grouping and Ordering): a "Group" caption with By project / By status / By time, | a "Sort" caption with Last updated / Created / Status first (trailing checks), | Show archived (check, disabled at 0; no count: it floated between the label and the check column, and Cursor's Archived item has none), | Collapse all (by project only, enabled while a listed project is expanded), Mark all as read (enabled while anything is unread or failed). Grouping and sort are remembered per device (`localStorage` `pi-web:sidebar-grouping`, `pi-web:sidebar-ordering`, `lib/sidebar-grouping.ts`).
- The sort applies to every list (project rows, Pinned, and inside status/time sections), newest first: by the family's latest activity, by the root's creation (rows then show the creation time), or Status first (needs you, then running, then the rest, each by activity; by status grouping it equals Last updated). Project order stays manual.
- Mark all as read takes each row's Mark as read path for every family with an unread member or an unseen error: marks clear at once, and the following status polls write the shared `readAt` (ten ids per poll, `/api/agent/running`) up to at least each error's time, so errors clear too.
- By status: Pinned stays first; then Needs you (waiting and error first, then unread; each newest first), Running (running, or idle with running subagents), Recent (the rest, newest first, with the same show-more paging as a project). Empty sections are not shown. Every project is listed, single-project mode included; a row of another project than the selected one puts the project's name before its time (`pi-bot · 3m`). Waiting and error rows keep their word.
- By time: Pinned first; then Today, Yesterday, Last 7 days, Last 30 days, Older by local calendar day of the sort's time (VS Code's time sections), every project listed as by status (project name before the time). Each section pages like a project (six rows, Show more), keeping running, unread, failed and the selected row visible.
- What by status and by time leave to by project: project rows and their menu (Show in Files, rename, move, select sessions, archive older), project drag, Collapse all, single-project switching (its project row opens the switcher, which names projects like the rows, path in the tooltip). The archive always lists by project. Search works in both.
- On a first visit (nothing stored in `localStorage`) the current project is open and the others folded; a stored choice is never replaced. The phone drawer is `min(86vw, 320px)` wide.
- Project rows: folder, name, the folded state dot (a folded row holding the shown session also takes its `--bg-selected` fill, see `docs/settings.md`, Sidebar reveal), and one hover action, + (New session in this project). Show in Files is in the project's context menu. Worktrees are switched, created and removed on the new-session page and switched in the Files view, not on the project row.

## New-session page
- An empty draft shows only the composer, with two text menus above it at its left edge (ChatInput's `attention` slot): the project ("pi-web ⌄": every listed project, then Open folder…, which also lists that folder as a project) and where it runs ("⑂ main ⌄": the branch glyph and the checkout's branch, the main checkout included). The second menu is one flat list of checkouts by branch name, main checkout first, no section label or "Project folder" wording, then one divider and New worktree…. Every row ends in the same slot: the check, with the remove action laid over it on hover/focus (`.menu-check-slot`; on touch at rest except on the current row; the main checkout has none; a dirty checkout asks for a forced removal), so checks never shift sideways. New worktree… whose branch field says "From <main checkout branch>". Both are named popovers (`role="dialog"`) of plain buttons, not listboxes: they mix choices with remove, a force confirm and a text field. A refused pick (the folder failed validation) keeps the menu open on the old cwd with the reason; picking again retries. Above them the Pi Web wordmark, then the app update notice when there is one; no tagline or example prompts.
- The page shows no file panel: entering it folds an open panel and leaving it for another session reopens it; sending the first prompt keeps it folded (the page becomes that session, and a panel popping open then read as unprompted). Opening the panel on the page keeps it open afterwards.

## Session state: one dot, one word
- A session has at most one state, shown as a 6px CSS dot (Cursor's size) (`SessionStatusDot`, `.session-status-dot` in `app/globals.css`), never an SVG badge or a count. Running (including a main session idle while its subagents run) is `--text-dim` and breathes (opacity 1 ↔ 0.35, 1.6s; still under `prefers-reduced-motion`); unread is `--accent`; waiting for input is `--warning-dot` (a brighter amber than the `--warning` text in light, so it stays apart from the red dot under deuteranopia); error is `--danger`. The four stay apart in both themes and with motion reduced (gray/blue/amber/red; only running moves). A root row without a state carries a faint idle dot (`data-status="idle"`, `--text-dim` at 25%, Cursor's read rows; lighter than the running dot so the two never read alike), so titles start after the same mark; it is not a state and has no label.
- Precedence, for a row and for a folded group alike (`lib/session-status.ts`): waiting = error > unread > running. A folded project (or the folded Pinned section, or the other-projects summary) shows only its most urgent dot, no counts; standing glyphs (cache keepalive, scheduled routines) are not states and stay.
- The row's dot sits in the leading slot left of the title (the project folders' column), so titles never shift. Waiting and error rows also replace the relative time with an 11px word in the same color ("Waiting", "Error"); running and unread keep the time. The row's native `title` adds the reason ("Waiting: <dialog title>", "Error: <provider message>"), and the row's context menu (right-click, long press) starts with the session title and the same reason; the pressed row keeps a hover tint while its menu is open. Reasons are one line, at most 120 characters, and reach the browser only through the status poll and session list (behind the web password when one is set).
- Pin is a hover action (with open-in-new-tab), and in the context menu on touch; pinned sessions are already in Pinned, so the row carries no pin mark. A linked worktree is a 12px branch glyph right before the time, as Cursor places its worktree mark (branch and path in its `title`), no branch text, so titles keep their width; with another project's name it stands in for the `·`. The glyph sits close to the time (3px); the time has a narrow tabular minimum (`3ch`), so `4h`/`23h`/`1d` rows align, and a longer word (waiting/error, Chinese times) widens only its own row instead of padding every row. When a row shows another project's name, the name shrinks first: the title keeps at least 88px. A long-press menu on phones opens below the pressed row (above it without room), inside the viewport, and starts with the session title like the right-click menu; Archive and Delete are split by a divider.
- Error: the session's last message is an assistant reply with `stopReason: "error"`, i.e. pi gave up after its automatic retries. The session scanner (`lib/session-list-scanner.ts`) derives it from the file, so it survives runtime disposal and server restarts; any later message (a retry that succeeded, a new prompt, a `!` command) clears it, and a Stop never sets it (`aborted`, or an `error` carrying only the fetch abort text, `isAbortedAssistantError()` in `lib/message-display.ts`, the same test the chat uses). pi omits each failed attempt it retries (a `context_edit` with `replacement: null`); an omitted failure is cleared too, so a Stop during a retry's wait is not an error. Its time is when the failure entry was written (the reply's own `timestamp` is its request start). Like unread it is a "you have not seen this" mark: hidden while the session runs or is on screen *and attended* (page visible, focused, input within 2 minutes: the same test as read writes and completion marks, so a failure in a background tab stays an error on the favicon), and cleared by the shared `readAt` (attention on the visible pane, or Mark as read). It keeps a family out of "show more" and out of archive-older, like running and unread. Subagents, side chats and routine-only runs stay silent, as they do for unread. A failed subagent does not reach its main session's row either: its result goes back to the main agent, which handles or reports it, and a main run that gives up is an error of its own; the unseen failure is the top bar's red Agents badge (Tabs and top bars). Mark as read targets at least the error's time and stays applied locally until the shared read reaches it. Errors count toward the favicon and the installed app badge (`lib/favicon-badge.ts`): the count covers waiting, error and unread sessions (a failed run that is also unread counts once), and the color is the most urgent kind — amber while anything waits, red while an unseen error remains, green for unread only.
- One state appears once per screen: the dot lives on the sidebar row (and on chat tabs while they exist). The conversation does not repeat it; inside a turn, only the live process row carries the running dot.
- What needs you sits above the composer, at its width (ChatInput's `attention` slot): a pending extension dialog, and after a run that ended in an error (the same test as the error state, not cleared by reading) one line "Error · reason · View output" (on phones the reason may wrap to a second line). The reason is the session list's `lastError.message` (the failed reply's own message while the list catches up). View output scrolls to the reply's error card and opens it, unfolding its process group if needed. There is no retry button; the existing Continue under the error card stays.

## Palette
- One neutral palette with light, dark and system modes; there is no palette choice (the warm Claude/Paper palette was removed: its sidebar and canvas could not be told apart). Values follow Cursor's Agents window and VS Code Modern, measured from their theme files, not by eye.
- Surfaces: light canvas `#ffffff`, sidebar `#f5f5f5` (1.09:1, the step that stands without a rule); dark canvas `#1c1c1c`, sidebar recessed below it at `#141414` (Cursor and VS Code both sink the sidebar in dark), floating surfaces `#272727`. Pure neutral greys, no warm or slate tint.
- Dark `--bg-hover` / `--bg-selected` are white overlays (7% / 10%, Cursor's approach), so a hover reads on the sidebar, the canvas and inside menus alike. Anything that covers content with them (row actions over a title, a remove action over a check) paints its own surface underneath: `linear-gradient(var(--bg-hover), var(--bg-hover)), var(--bg-panel)`.
- Accent is VS Code's blue (`#005fb8` / `#4daafc`); semantic colors after Cursor (light red `#ad1f2a`, amber text `#965700`, green `#00723e`). The PWA `theme-color` is the canvas (`--bg`), the color of the top bar under the status bar.

## Color budget
- Color is for things that need you (waiting, error), unread, and diffs (+/− and the Changes view's status letters). Everything else uses the three text tiers: process rows, the answer footer, file-tree status letters and folder change dots (`--text-dim`), the current project's folder (no tint), unsent-draft marks.
- Process steps carry no type icon: the tool name already says it (the icon only repeated it, and edit/write shared one). Only an error row keeps its red mark, inside the label width so its preview stays on the shared edge; the Continue action keeps its icon. A tool row is action, object and time: the name `--text-dim`, the object (command, path) `--text-muted`, so the object carries the row. Labels share an 8ch minimum so previews start on one edge (longer names, MCP `server/tool`, push theirs). Thinking keeps its word as the label (the row's only anchor, and what sets it apart from intermediate assistant text); its preview is `--text-dim`. Dropping the word was tried: thought sentences from the left edge alternated with commands from the label column and read as a zigzag. Intermediate assistant text starts on the same left edge. A command preview drops a leading `cd <session cwd> &&` (`lib/tool-preview.ts`); the expanded body and Copy keep it. Open content keeps the bodies' own 10px inset (clear of the collapse rail), and the list fades at its scrolled edges (`.scroll-fade-block`). Row actions (copy command, open file) appear on hover or focus with a fine pointer, always on touch.
- The answer footer shows model, duration (hourglass), `TTFT` (gauge) and end time (clock), each with its 12px icon. Copy and export appear on hover (always on touch).
- No cost in the transcript: not on a process header, its steps or the answer footer. Cost is in the context ring's tooltip and session panel.

## Tabs and top bars (one language, after Cursor)
- One surface: the chat top bar and the file panel's header are the chat's `--bg`, unruled; only the sidebar is `--bg-panel`. The sidebar has no right rule; rules stay on the file panel's left edge, the composer and cards.
- One tab look everywhere: chat tabs, the file panel's Changes / Files and its content tabs are 26px chips with a `--ui-radius-md` corner, 4px apart and 8px from the pane's edge, in a 40px top bar (`--workspace-header-height`, Cursor's height, shared by the sidebar's toolbar row) (`.chat-tab, .panel-view-tab, .panel-file-tab`). Resting text is `--text-muted` with no fill; hover tints `--bg-hover`; the current tab is filled `--bg-selected` with `--text`, the same as a selected sidebar row. Split: the focused pane's shown tab is current (`data-current`), the other pane's shown tab only takes `--text`, unfilled, so the bar has one fill; it keeps `--text` even as a preview tab, or nothing would tell it from its neighbours. Desktop chat tabs shrink to 120px; below that the strip overflows into the all-tabs menu. No accent or neutral lines above or below a tab, no rules between tabs (VS Code's top line for documents and underline for view switchers read as two languages here). Preview (unpinned) tabs set the title a tier quieter (`--text-muted`, filled or not; not the other pane's shown tab, above): Cursor and VS Code use italic, which this UI cannot render; the old dotted underline read as a shadow under the chip.
- Top bars hold only icons, so nothing there holds the eye: chat tabs, then conditional tools, `⋯` and the file panel toggle. Every top-bar icon button (chat top bar, file panel header with the terminal's actions, the tab strips' +, the sidebar toggle) is one class, `.workspace-header-action`: a 16px icon (stroke 1.7) resting at `--text-dim`, a click area as tall as the bar (30px wide), and one visible state, a 26px `--ui-radius-md` block behind the icon: `--bg-hover` on hover, `--bg-selected` while pressed or open (`aria-pressed` / `aria-expanded`) with the icon at `--text`, the same look as the sidebar toolbar. No accent lines; components set no colors, mouse handlers or `!important` overrides of their own. A tab's × is a 10px micro glyph at `--text-dim`, hovering to `--text` on `--bg-hover`.
- The two panel toggles sit at the bar's ends with mirrored glyphs: the sidebar toggle (left panel) and the file panel toggle (right panel). Neither swaps its glyph (a ☰ at both ends meant opposite things) nor rests pressed: the open panel beside it is the state, as in Cursor. Phones use the same two glyphs (the drawer included) at the same ends.
- Phones with two or more chat tabs show the tab strip under the top bar on `--bg`, unruled, 30px tall (2px around the chips) under a top bar that drops to 36px while the strip shows, so the two bars read as one block (icon ink to chip 12px instead of 15–17px), and the top bar drops the title (the shown tab names the session): sidebar toggle, conditional tools, `#`, `⋯`, file panel toggle. There is no Split right button: the tab menu's Split right has it (a lone tab's opens a new session on the right; with more tabs it moves that tab), and dragging a tab to the right half works too.
- Agents (`AgentsTopBarButton`) is a conditional top-bar tool whenever the session has subagents or side chats, right after "back to main agent", so switching to a child and returning happen in one corner (in the composer dock the two were at opposite ends of the pane, and a count there held the eye). The glyph is 14px, one step under the bar's 16px, because the badge sticking out of its corner makes the pair read larger (a 16px glyph plus badge read about 1.5× `#`; a 13px glyph under a 13px badge, the original button's sizes, read top-heavy); an 11px badge (4px corners) is centred on its top-right ink corner (`top: calc(50% - 11px); right: 4px`). Moving the glyph off centre or the badge along the diagonal was tried and dropped: the pair lost its centre against `⋯` and the panel toggle; pulling the badge inward covers the front card's corner and the glyph stops reading as two cards. The badge shows the dim total at rest; while subagents run, how many still run, on a solid `--text` badge breathing in fill (not opacity: the glyph would show through; still under reduced motion); `--danger` while a failure is unseen, running or not. The color says what the number counts, so there is no "2/6"; the tooltip and accessible name spell out running, failed and total. Only subagents count: side chats show the glyph without a number. A failure is `failed` or `interrupted` (a restart cut it), never `aborted` (a Stop); it is unseen until the Agents panel is opened, which marks it in `seenFailedAgents` in the shared sidebar state (`PATCH /api/sessions`, other devices follow through the session list). A resumed subagent that fails again stays seen.

## Composer (one row of controls, after Cursor and an independent design review)
- Nothing sits above the composer of a running session unless it needs you: a pending extension dialog, the run error line, or the near-full line (below). The new-session page keeps its project and worktree picks there, the one decision that page asks for; once the first prompt is sent the session panel the context ring opens shows the checkout (its directory with a copy button, and the branch).
- The dock (inside the composer, one row) separates roles: left are choices for the next message, text only (`+`, model, thinking level); right are the icon buttons. ## Borders: one closed border per line of sight
- Looking from the canvas inward, at most one closed border (four-sided `border`, or a full `box-shadow` 1px ring) is crossed. Stacked frames read heavy and fragment the page.
- Only self-contained objects get the frame: the composer, dialogs, menus/popovers, standalone code blocks and tables, cards.
- Everything inside a framed object is borderless: toolbar buttons and chips are ghost (transparent, hover fill) or a quiet `--ui-chip-bg` tint, nested regions use a tint. Internal divisions are single-side rules (`border-top`/`border-bottom`), never a smaller box.
- Exempt: an image's own edge (a faint ring over the pixels, e.g. `.image-thumb::after`, so white screenshots keep their shape), focus rings, drag/drop indicators, form controls (checkbox, radio, switch; text fields and secondary/danger buttons, which are the floating-surface color with a hairline `--ui-field-edge`, as in Claude's forms: a tinted fill read muddy), and floating layers (menus, popovers, dialogs, tooltips), which start their own count.

## Menus
- Touch targets: under `pointer: coarse` the visible size and the 26px row height stay as drawn; only the tap area grows, to about 40px, with a transparent `::before`/`::after` (one block at the end of `globals.css`). Where neighbours are closer than 40px the ring stops at half the gap (composer dock, sidebar header, project `+`), so some widths stay at 33-36px; the composer's context ring and ⋮ get a 5px gap instead. Send is 32px drawn on touch (negative margins keep the row unchanged). Rings must not sit under an `overflow: hidden` ancestor (the project `+` row action sets `overflow: visible` on touch for this); check with `elementFromPoint`.
- Quiet surface, clear rows (after Claude Desktop): `.menu-surface` is the only frame (10px radius, 4px padding); rows are `--ui-row-height` (26px, the same height as list rows, text buttons and single-line fields) of 12px text with 13px icons and a 6px radius (13px text read too large next to the 12px chrome; 24px felt cramped, 28px loose). Groups get their air from the dividers, not from taller rows.
- One clear surface: menus, popovers and dialogs sit on `--bg-elevated` (white in light, `#272727` in dark, a clear step above the `#1c1c1c` canvas), whatever area they open over; the settings dialog's nav, the tool-definitions list and embedded pages paint nothing of their own, and dialog headers are unruled. Shadows are light and short (`--ui-shadow-popover`/`-dialog`): the hairline border draws the edge, the shadow only lifts; they never borrow the canvas or sidebar tone. Anything painted inside them (sticky heads) uses `--bg-elevated` too.
- The Agents panel is only its rows: no head (title, totals and running counts repeat the rows and the top bar's badge) and no search (rarely used even in large families). With side chats every row ends in the shared check slot (`.menu-check-slot`), Delete laid over the check on hover, so checks keep one column whatever the row's status.
- Floating lists follow the same rules: the Agents panel, tab list, branch tree and autocomplete popovers have no per-row rules or resting tints, the current item is a trailing check, and a row action (close, remove) is a `.menu-surface-row-action`. The Agents panel shows running (each row's "Running") as the sidebar's gray breathing dot with a `--text-dim` word, never the accent: blue means unread. Outlines (minimap, mobile outline) have no checks, so the reading position keeps a plain tint.
- Two text tiers inside a menu: every label is `--text`; everything secondary (captions, meta, values, chevrons, the back row) is `--text-dim`. State never changes the text color: hover and keyboard tint the row, the check marks the choice, only `.is-danger` is colored.
- Row anatomy: optional `.menu-surface-label` group caption, then `[icon] label [dim meta] [trailing slot]`. The trailing slot means one thing per kind: `<MenuCheck>` (accent ✓) = current choice, a value + chevron = submenu, a row action (remove) = shown on hover, always on touch.
- One left edge: captions, options and actions start at the same x. No leading check gutter; the check is trailing. A leading icon is only for identity (a computer, a folder, a provider) and only when every row in the list has one; an action row then takes a matching icon (+), otherwise it is text like the rest ("Custom path…", "New worktree…").
- Action menus (context menus, ⋯) are text only: verb icons add noise without telling rows apart. Order rows by intent and split the groups with dividers (open | edit/state | archive/delete). Destructive items sit last and are `--danger` at rest (`.is-danger`).
- Selection is the check alone, in every menu: only the row under the pointer or keyboard is tinted, so a checked row and a hovered row never stack into two tiles. Check-less pickers (TimePicker) tint the picked value instead. The highlight leaves with the pointer: list-driven menus (`Select`, `ModelSelector`) clear their active row on `mouseleave`, and a click opens with nothing highlighted (keyboard opening starts on the current value). A row with its own action (worktree remove) is one hover unit; the action stays inside the tint.
- Options and actions ("New worktree…", "Open folder…") are split by an inset `.menu-surface-divider`, not by a border on the action row.
- Escape closes an anchored menu and puts focus back on its trigger (`useMenuDismiss`), unless focus had already moved elsewhere. The innermost layer takes the Escape (`preventDefault`): the drawer and the overlay file panel listen last (bubbling, on `window`) and skip a prevented one, so Escape in a menu, find bar or field inside them closes that first. Inner layers listen on an element or on `document` (bubbling; the explorer's file menu captures, like `useMenuDismiss`) and stand down while a modal is open, during IME composition, or when the event is already prevented: one Escape closes one layer (drawer row menu, delete confirm, selection, rename field; then the drawer). The find bar takes Escape from any of its controls, and cancelling the new-session "New worktree…" branch name returns focus to that row. Exception: a focused terminal keeps Escape (xterm consumes it for the shell), so the overlay or full-screen panel is closed with its own close button or the system Back there.

## Modal dialogs and confirms
- Modal shells (Settings, its nested dialogs, info, trust, directory picker, agent import, image generation) render through `components/ModalDialog.tsx`: the `<dialog>` element is the full-viewport scrim (the caller's backdrop class), its children are the surface. Layering is the browser's top layer, so no z-index; the latest `showModal()` is on top and everything else is inert.
- Escape belongs to the topmost dialog: `ModalDialog` handles it on keydown (preventDefault + stopPropagation, so an outer dialog stays open) unless a nested control already prevented it (a select menu, a rename field). Pass no `onClose` while the dialog must stay open (busy); if the browser still closes it, it is reopened.
- Android's system Back is a close request on the topmost `<dialog>` (Chromium's CloseWatcher), so it reaches `onClose` with no history entries of ours. Settings on a phone passes its header Back there, so Back goes up a level (detail → section → list) before it closes. A repeated Back without a tap in between gets an uncancelable `cancel` and then closes natively: `ModalDialog` answers only the `close` (one `onClose`, not two), reopening the dialog first so an owner that stays open (or opens a discard confirm on top) keeps it. Browsers without CloseWatcher (Firefox) still navigate away. The phone sidebar drawer and the full-screen (or 641–959px overlay) file panel take Back the same way, through their own `CloseWatcher` while open and covering the chat (`watchCloseRequest` in `AppShell`; the panel's follows the CSS breakpoint live through `matchMedia`, so resizing across 960px adds or drops it): Back closes them before it leaves the app. No history entries are pushed, so the URL (session, split) and forward/back are unchanged; the cost is that Firefox, without CloseWatcher, still leaves.
- Dialog anatomy (after Claude): `--ui-radius-xl` (14px) surface, 20px inset; a 14px/600 title, a quieter `--text-dim` line under it, the content, then the actions bottom-right. No header or footer rules. Cancel is a hairline `secondary` button (never ghost), the confirm button is `primary`, or filled `destructive` red for a destructive action, and is labeled with its verb ("Discard", "Delete", "Disconnect"), not OK.
- Confirmations use `useConfirm()` (`hooks/useConfirm.ts`): resolves a boolean; the message's first line is the title, further lines the detail (`"Discard unsaved changes?\nYour changes…"`). `{ danger: true }` starts on Cancel and fills the confirm red, `confirmLabel`/`cancelLabel` name the actions ("Keep editing" for a discard), `{ alert: true }` shows the confirm button only. `window.confirm`/`window.alert` are banned (guarded by `components/ModalDialog.test.mjs`). In-place confirms anchored to a context menu (delete project/session/file, force-remove worktree) stay as popovers with the same pair: hairline Cancel, then the filled action (`.is-danger` red, `.is-primary` for archive).
- Pane-scoped extension UI (`ExtensionDialog`, custom panels) is deliberately not modal: it can be collapsed while the chat stays usable. `ExtensionDialog` docks above the composer at its width (ChatInput's `attention` slot), a `--ui-radius-lg` card with a 14px/600 title, capped at `min(50dvh, 460px)`; collapse, countdown, keyboard and Esc cancel are unchanged; the footer says how to answer ("Click an option to submit · Esc cancels"). Custom panels (`custom()`, terminal-like) still float over the transcript.

## Prompt delivery and compaction

- A transport failure is not a rejection: once a normal prompt is confirmed idle, compare new persisted user entry ids with the pre-send history. If delivery cannot be confirmed, return text and images through the original tab's draft restore path and show a warning; never automatically resend. Steer/follow-up failures return immediately with the same warning.
- A built-in command lock restores only the textarea focus it displaced, after the fieldset is enabled; unchanged text also restores its selection. Pointer interaction elsewhere, Tab, moved focus, an open dialog or an unmounted editor cancels restoration. This is not mobile autofocus. Compaction history refreshes in the background so a newly typed draft and its selection stay mounted.
- `/compact` starts the existing compaction action without holding the composer's command lock. Keep typing, the queued rows and Recall usable. The composer adds no status UI for it: only the placeholder says messages will queue; Stop compaction stays in the controls menu; the result and errors use the existing feedback row. While a run is live its process row already reads "compacting"; an idle manual compaction shows that same live row (pulse, elapsed, label) on its own at the end of the transcript.
- On the SDK's explicit manual-compaction refusal, the session wrapper parks prompts (including images) in admission order; a parked plain prompt is listed as a follow-up (it runs after the compaction), an explicit steer stays a steer. Queue state is shared across tabs and survives a browser reload, not a server restart. Successful, failed and aborted compactions flush through the same admission chain; automatic compaction keeps using the SDK's streaming queues.
- Stop compaction only stops summarization: parked prompts still run, as in pi's TUI. Ordinary Stop snapshots and clears SDK delivery queues and returns them with parked prompts to the sending composer's draft before aborting; queued extension messages remain custom history without triggering another run (see `docs/extensions.md`), but dropped subagent reports stay unread in their wave (see `docs/subagents.md`). With no queued prompts neither action starts a run. Recall reads SDK delivery queues before clearing them, so image recovery remains fail-closed.

## Streaming code fences

While streaming, only an unambiguous top-level plain fence skips react-markdown
(`parseStreamingFence`). Math, Mermaid, SVG, indented fences, CR line endings,

## Extension terminal text

Plain-text cleaning and ANSI rendering both remove pi-tui APC cursor/fake-cursor
markers before rendering. Markers cannot span CR/LF: a truncated marker must not
consume later body text. Empty custom-panel normalization also cleans its fallback.

`AnsiText` renders the 16 ANSI palette slots (including indexed 0–15) as CSS
classes. Semantic red/blue/yellow and unbacked neutral text inherit the app palette;
other hues use our terminal's light/dark colors. Neutral backgrounds have separate
terminal black/white slots; neutral foregrounds on those backgrounds use terminal
neutrals too, including a contrasting default when no foreground was specified.
This keeps white-on-black and black-on-white readable in either app theme.
Explicit 256/24-bit colors stay exact. Keep `WebExtensionTheme`: it already emits
theme-independent ANSI slots.

## User shell output and busy admission

`!` output uses replacing `bash_output` snapshots, not SDK `bash_execution_update` deltas: the server retains only the last 16K UTF-16 units (at most 64 KiB UTF-8, without a leading half-surrogate), updates at most every 150ms, replays its latest snapshot on reconnect and clears it at completion/disposal. SSE may drop these under backpressure; persisted results remain authoritative. Each command has an id and a server `startedAt` that strictly increases within the runtime, including same-millisecond starts and clock rollback. Browsers retain only that server-time watermark (never compare it with their local clock) to reject older snapshots. An already-open idle observer adopts a valid snapshot through the same shell recovery path as initial mount. A newer command supersedes the observed card even if polling missed the idle gap: it invalidates the previous settlement loop/history reads, reloads the previous command's persisted result, and starts its own settlement loop. Late status responses, history completions and local POST completions cannot settle the newer card. The last command stays marked settled after its card clears so buffered snapshots cannot resurrect it. The pending card reuses `ToolCallBlock`'s result body, shows the last 20 lines, remains live while output arrives, and is replaced by persisted history on completion.

Truncated results keep their full-output actions in the expanded card's existing footer. If pi could not save the file, the footer gives the reason instead of offering file actions. Loading replaces the output above it and explicitly says the full output is shown (including an empty file). A 413 suggests downloading; missing files, malformed responses and network errors use localized unavailable feedback, never raw server errors. Failure leaves both retry and download available.

Unlike upstream, agent and user-shell execution remain mutually exclusive in this implementation. `sendQueued()` routes unquoted, image-free `!` / `!!` input to the command path, never to steering or follow-up; busy rejection explains the refusal and restores the originating draft. The server also refuses busy shell commands and refuses compaction while shell work is active. Parallel execution is deferred because this app has a parked compaction queue, shared Stop forced-cleanup deadline and post-bash subagent-report delivery; enabling it safely also requires reconciling SDK-deferred bash history against forced session reads, not just relaxing admission. Keeping mutual exclusion preserves existing Stop, completion and sidebar/favicon semantics.

## Tool step timing

Running tool steps reuse `StepDuration` and the existing row layout. The server
keeps each top-level call's start on `performance.now()`, replaying its start with
`elapsedMs` before the latest update. The client subtracts that elapsed value from
its own monotonic clock, never a server wall timestamp. Parallel calls therefore
have independent clocks. `tool_execution_end.durationMs` freezes the value while
batch siblings still run; reconnect keeps those frozen values and replaces only
running clocks. Result messages remove their clocks, and settlement clears the map.
SDK durations in persisted results still win; old history retains its timestamp
fallback. Thinking and standalone shell rows keep their existing timing behavior.
The wire already forwards start/end timing fields unchanged, covered by tests.

## Composer caret visibility

The existing capped-height resize fast path is retained: do not reset an already-overflowing 200px textarea to `auto` on each keystroke. Programmatic focus/restore/history/queue prepend, selection replacements (including extension `set_editor_text`'s `insertText` path) and HTML-link paste explicitly reveal a collapsed caret at the text's end. Mid-text selections retain their scroll; no mirrored textarea/caret measurement is introduced.

## Composer paste recovery

Plain-text paste stays native (important for large text). The paste handler remembers event text, selection and current value; a zero-delay check uses `replaceTextareaRange` only if no input arrived, nobody prevented the event, the same textarea is still mounted, and its value is unchanged. This recovers Chrome abandoning insertion when dictation tools rewrite the clipboard mid-paste. Image paste and HTML-link-to-Markdown conversion retain their existing paths; recovered text synchronizes the same React draft/selection state as other programmatic inserts.

## Completion notifications

Page and Web Push completion notifications share `pi-session-complete:<id>` and stamp `data.shownAt`. Both the page's service-worker delivery and the push handler check `getNotifications({ tag })`, quietly replacing a notification under 10 seconds old (`renotify: false`) whichever arrives first. Every valid push still calls `showNotification` (required to keep iOS subscriptions healthy), retaining icon/badge and same-origin click validation. Older/missing timestamps or unsupported/failed listing alert normally; listing failure does not trigger window-notification fallback.

## Clipboard feedback

`copyText()` rejects refused `execCommand` copies as well as thrown failures and always removes its temporary textarea. The `/copy` command instead reports a localized permission-failure notice. `copyPendingText()` still starts Safari's pending-Blob clipboard write inside the user gesture. FileViewer/Mermaid/math already use the shared `MarkdownCopyButton`, which handles rejection; tab path actions also already handle it.

## Images

- Prompt picks, paste and chat drops share `ChatInput.readPromptImageFile()`: preserve original bytes and sniff PNG/JPEG/GIF/WebP MIME from the bytes, keeping the 10 MiB/file and 10-image limits. The browser only falls back to the existing 2000px / JPEG 0.85 white-background re-encode at **4.5 MiB of base64** (3.375 MiB of file bytes) or above, including GIFs. This is conservative even for ordinary prompts: pi skips resizing when disabled. As before, unavailable/failed browser decoding or canvas encoding falls back to the original. `@` image mentions remain paths in the prompt, not browser-read attachments.
- Installed pi SDK 1.6.1: ordinary prompts normalize after `before_agent_start`, using the routed/current model's `inputLimits.images.resize`. `images.autoResize` defaults to true; missing model/profile fields fall back to 2000×2000, **strictly below 4,718,592 base64 bytes**, JPEG quality 80. In-limit PNG/JPEG/GIF/WebP bytes stay unchanged; other decodable formats convert to PNG. At each size, resizing prefers the smaller of PNG and JPEG at the configured quality (default 80), then tries JPEG qualities 85/70/55/40 if neither fits. If none fits, it shrinks dimensions by 0.75 and retries. Decode/conversion/resize failure omits the image with a text hint, never an oversized raw fallback. With auto-resize off, supported formats pass through unchecked (other formats still attempt PNG conversion); a 10 MiB PNG can reach the provider unchanged. Since pi 1.5.1 steering/follow-up images are normalized the same way when pi delivers them, so the wrapper queues them as sent (`lib/prompt-image-sdk.test.mjs` pins both paths). Image-generation dialog picks keep their separate >1 MiB, non-GIF compression because they do not use prompt normalization.

- Read cards keep the image visible even when the model received a placeholder. A warning beneath the image names that model in both collapsed and expanded views.
- Two kinds of image, two treatments. **Context the user gave the model** (composer attachments, `@` image files, user-message images, the image dialog's sources) is a numbered row of uniform 64px square thumbnails (`.image-thumb`, cover, top-aligned, `+N` after 6): the composer and the sent message look the same on purpose. **Content to read** (assistant markdown images, assistant image blocks, tool-result images, generated images) is shown size-capped (`min(60vh, 420–520px)`, never the natural size) and opens the viewer on click. Do not render a raw `<img>` in a message; use one of the components in the file map.
- Order matters: images go to the model in array order and `generate_image` refers to them as `attachment:N`, so the composer and the image dialog show the index and keep the array order the user sees. The dialog's edited result is `lockedCount` (fixed first, not movable or removable). `ImageAttachmentStrip` keys items by `src` length + tail + occurrence, never by index.
- `ImageViewer` is one component for mouse and touch (Pointer Events, `touch-action: none` on the stage). Mouse: wheel/±/0 zoom, drag to pan, click the image or backdrop to close, `←/→`; keys are bound on `document` (capture) because the focused button disables on the last image and focus falls to `<body>`. Touch: swipe switches (previous/current/next are rendered as a track, and the swipe target is one slide pitch = width + `SLIDE_GAP`, so the neighbour lands exactly on the centre slot; any mismatch shows as a jump at the end), pinch and double-tap zoom, drag down closes, a tap toggles the controls, and the controls start hidden with an opaque black, edge-to-edge picture. Arrows and zoom buttons are hidden under `pointer: coarse`. There is no double-click zoom on desktop because click closes.
- Zoom is shown as real scale: `zoom × fit`, where `fit` is displayed size over natural pixels (`fitOf`, the tighter axis), so 100% is the natural size. The minimum is fit-to-window, the maximum 400% of natural. Clicking the percentage toggles fit and 1:1.
- Touch reorder is done in the viewer, not by dragging thumbnails: an editable set (`edit` prop) shows move earlier / remove / move later there. A long-press drag among 64px thumbnails was hard to aim and fought scrolling. Desktop reorders by dragging thumbnails or `Alt+←/→`.
- Enter and exit are one plain fade of the whole overlay (0.25s / 0.2s); the full-screen touch motions are slower (340ms) than menu-surface-in (0.12s) because travel distance changes the perceived speed. All closes go through `requestClose()` so the exit plays before the parent unmounts.
- Deferred image and thinking requests look up the entry in the live session first. Disk lookups use the session read cache or, above its file-size limit, an asynchronous JSONL scan; files without entry IDs still need SDK migration.
- History (`deferMedia`) serves user-message and tool-result images as URLs to `/entries/[entryId]/tool-result-image`, which returns the original bytes (no resize/recompression) with an immutable cache header; user images that are too large or of an unsupported type stay inline, never dropped. Edit/restore (`getUserMessageDraftImages`) fetches URL images back to base64; fork and export read the file server-side. Thumbnails use `loading="lazy"` and `decoding="async"`.
- Dev note: after editing `app/globals.css`, Turbopack has repeatedly kept serving the old CSS (HTML links a stale chunk). Confirm with `document.styleSheets`; appending and removing a comment forces a rebuild, and a restart with `.next` backed up (see troubleshooting) fixes a persistent case.
